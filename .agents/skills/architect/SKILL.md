# Noted Architect

You are the architecture gate for this repo. Load this skill before creating packages, apps, routers, schemas, shared configs, or cross-cutting patterns, and before reviewing structural refactors.

## The shape (from create-t3-turbo, verified 2026-09-23)

- pnpm + Turbo v2 pipeline (`turbo.json`): `build`, `dev`, `lint`, `typecheck`, `format`, `synth` run through turbo with shared caching; CI mirrors the same gates.
- `apps/*`: thin platform shells (Next.js web first; Electron/Capacitor later — never Expo). Shells own SDKs, auth adapters, env wiring, and navigation only.
  - `apps/mobile` bundles the native offline client with Vite and loads it from Capacitor local assets. It supplies the PowerSync Capacitor driver (native Community SQLite) and opens sign-in in the system browser. `sync:local`/`run:local` use the local backend; production builds use HTTPS and production backend defaults. Generated web assets live in ignored `dist/`; committed Android project files register native plugins.
  - `apps/desktop` bundles the same native offline client with Vite. Electron serves its assets from a secure `noted://app` protocol with path containment, sandboxed isolated renderers, no Node integration or preload, and restricted external sign-in navigation. SQLite runs through the PowerSync Web SDK OPFS driver. The NSIS installer includes renderer assets; remote website loading is no longer the startup path.
  - Hybrid native device features ride Capacitor plugins: the plugin package lives in both shells (`apps/mobile` for the native implementation, `apps/web` for the JS API loaded lazily), calls sit behind a `src/platform/*` adapter gated on `useNativeShell()`, and desktop keeps the web fallback. Permissions are declared in the Android manifest and requested at capture time.
- `packages/*`: one responsibility each — `api` (tRPC routers), `db` (Drizzle schema + client), `domain` (shared domain rules: time windows, coordinates), `infra` (AWS CDK app: production media bucket plus its server identity), `media` (S3 object storage plus image/video variants), `queue` (QStash publishers, job schemas, worker verification), `realtime` (Redis-backed realtime: room pub/sub, board cache, presence), `validators` (pure zod schemas), `offline` (client-only PowerSync schema, local mutations, and outcome handling), `native-client` (shared native offline workspace, account/attachment lifecycle, and local tRPC adapter; shell-supplied auth, database/file factories, and browser opening), `experience` (shared illustrated home scenes, presentation contexts, motion, sound, and capture UI), `ui` (shared visuals), plus shared `tsconfig` / `eslint-config` / `prettier-config` / `tailwind-config`. No package grows a second job; split instead.
- Jobs publish on mutation, except scheduled sweeps: a QStash Schedule POSTs the envelope to a thin worker route (same verify → parse → service shape). Scheduled envelopes are global (no homeId); the handler resolves scope by lookup, moves each row inside one delete-guarded transaction, and stays idempotent under retry and overlapping runs.
- Production web releases use `apps/web/vercel.json` and `build:vercel`: compile first, then apply committed Drizzle migrations under one direct PostgreSQL session lock, then let Vercel publish. Only `VERCEL_ENV=production` runs migrations; previews skip them and unknown environments fail closed. Reuse the deployed database credentials; the migration runner resolves Neon pooled hostnames to their direct counterpart. Local builds do not migrate, and SQL is never generated during deployment.
- Env: dotenv-loaded root `.env` plus typed env validation per app; server secrets never cross into client code.

## Hard rules

1. tRPC routers are the only API definition: zod input validation, end-to-end inferred types, superjson. Never hand-write an API client or re-declare a call signature in a second place — the v1 `api-client` fetch-wrapper shape must never return (see `docs/decisions/0005-rebuild-on-clean-foundation.md`, D8).
2. Routers stay thin: auth plus membership checks, input validation, then a service call. No SQL in routers, no business rules in components.
3. Firebase Google auth behind a small server seam (verify ID tokens, resolve the app user); shells supply sign-in UI only.
4. Drizzle owns server persistence: schema plus migrations in `db`, one client, no raw SQL outside migrations and seed except established transaction-lock expressions. Client content persistence belongs in `offline`: the PowerSync schema, parameterized content reads, and atomic content mutations, with supported SDK transaction/queue APIs. `native-client` owns account/subscription/attachment lifecycle queries against documented application tables and adapts the inferred tRPC contract to those local operations; it never modifies SDK internal tables. Never mutate PowerSync internal tables. SDK construction and account credentials belong to platform shells.
5. Styling: Tailwind utilities for UI; bespoke CSS only for the board art layer.
   - Scene artwork includes the illustrated login room: scoped scene CSS may own artwork, screen alignment, and reduced-motion-aware transitions. Interface layout, copy, and controls remain Tailwind.
   - App typefaces use shared Tailwind theme tokens. The web shell bundles Kalam in `src/styles/fonts`, loads it once in the root layout, and applies `font-handwritten` as the default; feature components inherit it rather than loading their own copies.
   - Approved brand masters live in `apps/web/public/brand`; headers share the web shell's `features/brand/noted-logo.tsx` presentation with Next Image. Browser and Apple icons use Next's root app metadata file conventions, with small exports derived from the approved icon. Keep artwork masters out of the runtime image path.
   - Shared paper texture and button artwork live in `packages/ui`; screens supply accessible controls around this decorative art. The web shell shares login/button/link response through `features/motion/use-paper-motion.ts`. The homes chooser keeps data fetching and mutations in the web shell, uses Tailwind for layout, and separates page/workspace entrances from keyed card entrances so query updates only animate new cards. All motion respects reduced-motion preferences.
   - Home scene shading and bounded illustration masks belong in `styles/home-scene.css`. Scenes fill the viewport below a compact header, with small tool overlays and focus-only native keyboard navigation; the TV leaves room around its frame for the liquid backdrop. The web shell owns pointer capture and navigation; pure swipe direction, scene wrapping, and ready-clip playlist selection live in `packages/ui`. Scene entrances and album turns are keyed to user navigation, never query refreshes. Shared dialogs portal to the document body so scene transforms cannot contain them; they trap and restore focus. The web shell owns clip playback, ready-clip automatic advancement, the clip action menu, fullscreen lifecycle/focus, VHS texture, and gesture-created Web Audio receiver sound; autoplay first attempts sound on and retries muted only on browser autoplay rejection, the sound control stays visible in normal/fullscreen views, explicit mute survives other interactions, off-screen/hidden media pauses, and audio closes on scene unmount. The TV backdrop uses dedicated landscape/portrait sala artwork with the shared lazy memory renderer's room variant and source aspect ratio, reveals only after readiness, and respects reduced motion/hidden-tab redraw limits. Manual clip scrolling wraps one finite list at its boundaries; fresh wheel/touch gestures consume remaining momentum without duplicating players. The web shell animates wrap destinations through temporary adjacent slots with GSAP, restores layout on completion/resize/hiding/unmount, and skips motion when reduced motion is requested. Preserve normalized fridge coordinates and exclude draggable posts from scene gestures; vertical TV scrolling stays inside its clip viewport.
   - The public login uses a bounded illustration behind a DOM invitation. Its liquid-memory renderer belongs in `packages/ui`, contains no auth or domain logic, and uses a dedicated export for lazy loading React Three Fiber. GSAP owns interface motion and completion-driven navigation in the web shell. Keep the illustration hidden until the renderer's first frame; a static image is reserved for renderer failure. The shell owns the accessible controls and renderer error boundary. Reduced motion renders a still image and skips the pull; hidden tabs pause redraws. Shared remainder-preserving frame timing keeps login at 24fps on phones and 30fps on desktop, with login pixel density capped at 1.25. Room scenes use a separately compiled lightweight shader with integer noise hashing and one artwork sample, render at 30fps, and let the renderer adapt pixel density up to 2 within a 1.5-million-pixel target (minimum density 1), lowering it under sustained missed frames and recovering gradually when stable.
6. Theme system rules: fixed board and CSS slots; a theme is art plus a validated manifest JSON; theme changes are creator-only; posts keep their colors across theme switches.
   - The home shell owns one gesture-created Web Audio context and shared mute preference in `features/sound/home-sound.tsx`; individual scenes own and disconnect their sound nodes. Empty TV channels have a low-level receiver buzz, paused clips stay quiet, and playback replaces the idle buzz. The fridge entrance waits for both appliance layers, closes its illustrated face and attached posts once per scene mount using the web shell's GSAP hook, and triggers a short synthesized seal thump from the closing tween completion, followed by a quiet CC0 recorded glass rattle decoded before contact. Late or failed decoding never delays or replays the cue. Reduced motion or asset failure shows the closed fridge immediately without entrance sound; resize, hidden tabs, and scene exit cancel the motion and pending sound. Shared BoardStage supplies a fixed casing, interior, hinged face and readiness callback. One shared SVG aperture cuts the casing and clips both interior and face; the closing face occludes the stationary interior without crossfading or replacing the outer cabinet. Post coordinates stay measured on the full normalized surface.
   - The photobook uses its own landscape/portrait nighttime bedroom with the shared readiness-gated memory backdrop. Its cloth cover stays still while the web shell's GSAP turn carries outgoing photos across the spine on a curved, double-sided sheet with a moving shadow. Temporary inert DOM snapshots belong to the web hook; React owns the live spread beneath them. Once per scene mount, an introductory leaf turns onto the first spread after its query succeeds, including an empty book; subsequent turns require explicit navigation, and data refreshes never replay the entrance. Repeated navigation finishes the active sheet before taking another snapshot; resize, hidden tabs, reduced-motion changes, and unmount discard the overlay and restore photo interaction. Four archived entries form two sequential pages, with original images opening read-only in the shared modal and removal errors staying in that modal. Archived clips (swept or manually moved) autoplay silently and loop inside the visible spread, keeping a poster or placeholder underneath until playback starts. The web shell attaches video sources only for visible clips, releases them on page/scene exit, hidden tabs, or an open media modal, and restores playback when visible again. Turning sheets carry bounded canvas snapshots of video frames, never cloned media sources; the live player stays beneath the paper. Clicking still opens the shared modal with muted autoplay and playback controls; expiring TV reels show a countdown, while fixture reels carry no expiry and stay permanently. Status stays left and compact paging controls right; native buttons along the outer book edges also turn pages, stop at the first/last spread, and leave photo hit areas clear. Reduced motion shows still artwork and skips leaf turns.
   - BoardStage owns the fixed 3:5 appliance and an inset door surface, and accepts the web shell's backdrop as a ReactNode. The afternoon fridge uses its own generated landscape/portrait kitchen and transparent cream appliance; image readiness gates the appliance reveal. The shell supplies the shared memory renderer. Decorative paper grain and stable enamel magnets belong to posts. Pure card-size-aware containment belongs in packages/ui; the shell measures cards and the door with ResizeObserver and uses the same bounds for display and drag targets. Account for the magnet's top overhang, cap content against door container size, and remeasure loaded images and viewport changes. Existing edge coordinates clamp visually without automatic persistence; explicit drags save bounded normalized coordinates. Both post kinds open accessible dialogs: notes edit, photos view their original image without editing. Delete/archive controls live in the dialogs; BoardView owns optimistic removal, rollback, and successful-removal Undo snapshots so a disappearing post cannot unmount its mutation owner. Realtime snapshots never replay the scene entrance.
7. Dependency direction: apps depend on `api` and `queue` (worker routes verify through it), while `api` depends on `auth`, `db`, `domain`, `media`, `queue`, `realtime`, and `validators`; `auth`, `db`, `domain`, `infra`, `media`, `queue`, `realtime`, `ui`, and `validators` depend on nothing internal. `offline` may import `validators` and PowerSync common APIs, never backend packages or app shells; platform SDKs are supplied by shells. Backend integration tests may use test-only database drivers. `native-client` may import `offline`, `ui`, `validators`, PowerSync common, and API types only. It never imports backend implementations. Native Firebase configuration and platform SDK construction stay in the shells. Native sign-in uses an authenticated browser approval and a short-lived verifier-bound exchange; only the auth seam mints marked Firebase custom tokens. Nothing imports `infra` at runtime — it is deploy-time only. Lint must enforce it; flag any new edge that breaks the direction.
8. Runtime boundaries are visible at the top of source files and enforced by the built-in ESLint `no-restricted-syntax` configuration in `tooling/eslint/boundaries.ts`: backend packages use `import "server-only";`, client UI uses `"use client";`, and shared `domain`/`validators` stay unmarked. App files declare their boundary; `"use server";` is only for Server Functions. Tests and type declarations are exempt. Use standard Node conditions and the marker package's own empty entry for backend tools/tests, not custom shims. Deploy-time tools (db scripts, the CDK app) run under `--conditions=react-server`.

9. AWS resources are CDK-owned in `infra`: one stack per lifecycle, synthesized template plus `assertions` tests gating every change (`synth` runs credential-free in CI via an environment-agnostic stack). Stack outputs feed production env; IAM policies mirror exactly the actions the consuming package calls; access-key material is created manually and injected via env, never committed.

## On every structural change

- Name the turbo package or app the change belongs in; if none fits, propose the new package and its single responsibility first.
- Follow the nearest existing pattern; if the change needs a new pattern, update this skill in the same change.
- Reject bespoke framework-lets: hand-rolled clients, custom wrappers, or one-off scripts that duplicate a turbo task.

## Shared native content and media (2026-10-25)

- `experience` owns the fridge/TV/photobook presentation previously in the web shell, including home navigation, motion, sound, media UI, and its auth/tRPC/offline runtime contexts. It imports backend API types only, never backend implementations. Web and native shells supply their providers; shared scenes have no Next.js dependency. Styling lives in `experience/src/styles.css` and the shared Tailwind theme. Existing scene behavior rules above now apply to this shared owner.
- `native-client` imports `experience` and uses the same inferred tRPC router contract for local content procedures. Local queries watch SQLite; local mutations use `offline` atomic operations. Online administration/presence remain backend calls. Native content correctness never depends on SSE notifications.
- Metadata and original bytes use separate supported PowerSync queues. Stable client IDs, persisted originals before local acknowledgement, server-authorized checksum tickets, verification/commit before upload acknowledgement, and durable job intents are required. Android supplies filesystem/file-transfer/share adapters; desktop supplies OPFS. Cache eviction cannot delete pending originals or pinned work. Confirmed revocation follows discard-and-notify; network/auth failure preserves work.
- Media worker completion closes durable intent; publishing alone does not. Release builds upsert scoped QStash recovery/sweep schedules after compile and migrations. S3 origins remain CDK-owned. Existing PowerSync publications are extended through committed SQL migrations; fresh setup documents the explicit table allowlist. Never publish receipt or worker-intent tables.
- Build success and adapter/integration tests do not establish physical-device offline, maximum-video memory, account switching, or complete crash/recovery acceptance. Record those separately in `docs/plans/offline-first-architecture.md`.
